## 1. 核心机制

### 1.1 流程定义

```
发布物品 → 申领者提交需求 → 原物主自主选择 → 到付寄出 → 申领者提交反馈闭环
```

### 1.2 角色定义

- **原物主（赠主）**：把完好有价值但不再使用的物品发布到平台，自主选择最合适的申领者
- **申领者**：提交真实使用需求，申请免费获取物资，收货运费到付
- **平台**：非盈利运营，永不抽成，财务公开

### 1.3 核心链路

| 步骤 | 动作 | 角色 |
|------|------|------|
| 1 | 拍摄物品照片，填写描述、分类、标签、所在城市 | 赠主 |
| 2 | 浏览物品列表，按分类/关键词/同城筛选 | 申领者 |
| 3 | 提交申领理由（≥30字）+ 收件地址 + 手机号 | 申领者 |
| 4 | 查看申领者列表，选择最合适的人 | 赠主 |
| 5 | 到付寄出，快递员上门收款 | 赠主/快递员 |
| 6 | 7天内提交使用照片 + 感谢信 | 申领者 |
| 7 | 评价反馈质量（点赞/标记敷衍） | 赠主 |

## 2. 产品模块

### 2.1 注册与认证

- **方式**：微信授权登录，调取微信实名信息
- **体验**：一键完成，零摩擦
- **门槛**：不认证只能浏览，不能参与
- **MVP 阶段**：跳过登录，使用本地模拟用户验证核心流程

### 2.2 浏览与发现

- **首页**：最新发布 / 分类入口 / 搜索入口
- **筛选**：按分类、是否同城
- **搜索**：关键词搜索 + 标签
- **物品详情页**：
  - 照片轮播
  - 描述 + 新旧程度
  - 赠主信息（昵称 + 小红花数量）
  - 申领按钮
  - 可见当前申领人数

### 2.3 申领流程

| 规则 | 内容 |
|------|------|
| **提交内容** | 申领理由（≥30字）+ 收件地址 + 手机号 |
| **撤回** | 赠主决定前 = 减少一个申领者；决定后 = 单品重新匹配 |
| **修改理由** | 限 3 次修改机会 |
| **重复申领** | 同一物品被拒后不可重复申领 |
| **每人每物** | 只能申领一次 |

### 2.4 等待与选择

- **申领者可见**：当前申领人数
- **拒绝通知**：「有更需要的人，因此暂时未被选中」（不说原因）
- **被选中后可拒绝**：突然不需要时可拒绝，赠主重选；无其他申领者则物品重回产品池
- **赠主决策**：无硬性时限，但超时将收到系统提醒

### 2.5 收货 & 运费

- **运费方式**：到付，快递员上门时由申领者付款
- **默认快递**：顺丰
- **低价快递**：不能要求，除非赠主愿意
- **拒收**：纳入黑名单，一年内不接受许愿
- **运费异议**：不能以运费高为由拒收

### 2.6 反馈闭环

- **时限**：收货后 7 天内
- **内容**：使用照片 + 感谢信
- **照片可见性**：仅赠主可见
- **案例展示**：文字隐去敏感信息后可能被抽取放上"案例墙"（需双方同意）
- **评价机制**：申领者不能对赠主打分/评价

### 2.7 信用体系（高道德标准）

**设计原则**：申领门槛低，但违规成本极高。

| 行为 | 后果 |
|------|------|
| 按时提交完整反馈 | 信用 +10 分 |
| 反馈质量高（被赠主点赞） | 信用 +15 分 |
| 超时未反馈 | **拉黑 3 个月** |
| 反馈敷衍（赠主标记 + 平台复核） | **拉黑 3 个月** |
| 拒收 / 不付运费 | **拉黑 1 年** |
| 被证实转售（赠主举报 + 核实） | **永久拉黑** |

**拉黑规则**：
- 拉黑期间可浏览物品，不能申领 / 不能许愿
- 拉黑到期后自动解封 + 开屏提示"重新遵守社区约定"
- 反馈敷衍需赠主标记 → 平台人工复核，避免赠主恶意标记

**小红花（赠主激励）**：
- 赠主收到的小红花 = 虚拟"赞"
- 成功的申领者（收到物品后）可给赠主送一朵小红花
- 案例展示页浏览者也可点赞送小红花
- 小红花数量 = 赠主的社会贡献度量

## 3. 防作弊机制

| 风险 | 解法 |
|------|------|
| **黄牛转卖** | 物品价值区间控制（优先二手市场难以变现物品）；申领历史模式分析；反馈中须展示物品当前使用场景 |
| **批量薅物** | 五重身份锚定（手机+微信+设备指纹+IP+地址）；频次硬限制（低靠谱值月限2次，高靠谱值月限5次） |
| **假造需求** | 核心解法：判断权还给原物主自主选择；辅助：保持最低字数要求（≥30字） |
| **虚假发布** | 多角度实物照片；初期人工审核；举报下架 |
| **反馈造假** | 照片必须含物品 + 使用环境（纯特写无效）；超时未反馈自动拉黑 |

## 4. 数据库 Schema

10 张表，详见 `supabase/migrations/001_schema.sql`。

| 表 | 说明 | 关键字段 |
|----|------|----------|
| `profiles` | 用户扩展 | id (PK), nickname, trust_score, completed_cycles, red_flowers, total_given, is_blocked |
| `categories` | 物品分类 | id (PK), name, icon（10 个预设） |
| `items` | 物品 | id (PK), giver_id, category_id, title, description, tags[], city, status, expires_at |
| `item_images` | 物品图片（独立表） | id (PK), item_id, url, thumbnail_url, sort_order |
| `applications` | 申领记录 | id (PK), item_id, applicant_id, reason, address, phone, edit_count, status |
| `feedback` | 反馈闭环 | id (PK), item_id, applicant_id, giver_id, thank_letter, quality |
| `feedback_images` | 反馈图片（独立表） | id (PK), feedback_id, url |
| `trust_events` | 信用事件 | id (PK), user_id, event_type, score_change, block_duration |
| `red_flowers` | 小红花 | id (PK), giver_id, sender_id, item_id |
| `notifications` | 通知（轮询） | id (PK), user_id, type, title, body, related_item_id, is_read |

## 8. MVP 阶段说明

当前 MVP 使用**本地模拟数据**验证核心流程，不依赖任何外部服务：

- 3 个预设用户（小林 / 阿花 / 乐转赠运营）
- 6 个示例物品
- 10 个分类
- 用户切换器（导航栏右上角）

**接入 Supabase 后**，只需替换 `src/lib/mock-data.ts` 中的 API 函数实现为 Supabase 查询，所有页面代码无需改动。
