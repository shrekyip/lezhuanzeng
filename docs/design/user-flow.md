# 乐转赠 - 用户流程与机制设计

> 本文档从用户视角定义平台的核心流程与机制规则，供后续产品原型和开发参考。

---

## 一、注册与认证

### 赠主（发布物品的一方）

| 项目 | 规则 |
|------|------|
| 注册方式 | 微信授权登录即可，不强制要求手机号 |
| 实名认证 | **不需要**。赠主无偿赠与，无需实名 |
| 信用/等级 | **不需要**。赠主的回报是情感层面的——收件人的感谢信和小红花 |
| 账号关系 | 赠主和申领者**账号分开**。赠主如需申领物品，需另行注册申领者账号 |

### 申领者（申请物品的一方）

| 项目 | 规则 |
|------|------|
| 注册方式 | 微信授权登录 |
| 实名认证 | **必须实名认证**（具体方式待定：身份证/人脸/微信实名信息） |
| 信用体系 | 待定（见后续模块） |

## 二、发布物品（赠主视角）

### 2.1 发布表单

| 字段 | 必填 | 说明 |
|------|------|------|
| 物品照片 | ✅ | 至少 1 张，上限 9 张 |
| 物品名称/标题 | ✅ | 如"九成新 Kindle Paperwhite" |
| 分类 | ✅ | 数码电子、书籍文具、母婴用品、家居生活、服饰鞋包等 |
| 物品描述 | ✅ | 使用情况、瑕疵、尺寸、品牌等 |
| 成色/新旧程度 | ✅ | 全新 / 几乎全新 / 轻微使用痕迹 / 有明显痕迹 |
| 估算价值 | ✅ | **须 ≥ 50 元**。由赠主自行估价，低于 50 元不得发布 |
| 邮费方式 | 自动 | **默认到付**，申领者承担运费 |
| 期望申领理由 | 选填 | 赠主可要求申领者说明为什么需要这件物品 |

### 2.2 物品规范（禁止发布）

- ❌ 活体动物
- ❌ 估值低于 50 元的物品（运费不划算，无赠与价值）

> 其他品类不做硬性限制。如物品涉及安全/卫生风险，赠主应在描述中如实说明，申领者自行评估判断。

### 2.3 数量与时限

| 规则 | 说明 |
|------|------|
| 同时在线物品上限 | **不限制** |
| 在线时长 | **不限制** |
| 定期确认机制 | 每 **30 天**系统提醒赠主确认物品是否仍在；7 天内未确认则自动隐藏 |
| 赠出后冷却期 | 无（赠主随时可以发布新物品） |

### 2.4 物品状态流转

```
草稿 → 已发布(接受申领中) → 已选定受赠人(待发货) → 已发货 → 已完成(收到反馈)
                 ↓                        ↓
      30天未确认→自动隐藏        手动下架(赠主主动撤回)
```

## 三、申领与匹配

### 3.1 匹配模式

| 项目 | 规则 |
|------|------|
| 模式 | **赠主自主选择**（非先到先得）。赠主浏览所有申领理由，挑选最打动自己的受赠人 |
| 核心理由 | 平台的初心是保证赠主体验，赠主有权决定物品给谁、甚至不给 |

### 3.2 申领与决策流程

```
赠主发布物品 → 开放申领 → 申领者提交申请 → 赠主收到通知
                                              ↓
                              赠主在一周内浏览申请，做出决定
                               ↙        ↓        ↘
                      选定受赠人   延长申领期   拒绝赠出
                      （最多延期2次）（关闭该物品）
```

### 3.3 时间规则

| 规则 | 说明 |
|------|------|
| 决策窗口 | 收到第一份申领后，赠主**原则上 1 周内**确认匹配结果 |
| 延期机会 | 赠主可延长决策窗口，**最多 2 次**（每次延多久待定，建议每次 1 周） |
| 拒绝赠出 | 赠主有权拒绝所有申领者，物品直接下架（无需理由） |

### 3.4 申领表单（申领者提交）

| 字段 | 必填 | 说明 |
|------|------|------|
| 申领理由 | ✅ | 说明为什么需要、如何使用这件物品 |
| 收件地址 | ✅ | 仅赠主可见，用于发货 |
| 联系方式 | ✅ | 手机号，方便快递联系 |

### 3.5 申领者限制

| 规则 | 说明 |
|------|------|
| 待确认申领上限 | 同一子类目下最多同时持有 **3 个**待确认申领 |
| 跨类目不限制 | 不同子类目各自独立计数，不互相影响 |
| 释放时机 | 申领被确认（无论成败）或申领者主动取消后，名额释放 |

> 例：用户可以在「数码电子」下申领 3 件 + 「书籍文具」下申领 3 件，互不影响。

## 四、物流与隐私

### 4.1 发货流程

```
赠主选定受赠人 → 系统通知申领者 → 赠主查看收件地址 → 赠主自行寄出（到付）
                                              ↓
                              填写快递单号 → 申领者追踪 → 确认收货
```

### 4.2 规则

| 规则 | 说明 |
|------|------|
| 邮费 | **默认到付**，申领者承担运费 |
| 发货时限 | 选定受赠人后 **3 天内**寄出，超时可取消匹配 |
| 快递选择 | 赠主自行选择快递公司 |
| 地址可见性 | 申领者地址仅被选中的赠主可见；**赠主手机号对申领者隐藏**（快递面单上的寄件人电话不可避免，但平台内不暴露） |
| 自取选项 | 支持。赠主发布时可勾选「支持同城自取」，申领者可选择自取 |
| 拒收/不付邮费 | 申领者信用扣分；物品退回赠主，赠主可重新上架或联系下一位申领者 |

### 4.3 隐私保护原则

- 赠主之间互相不可见对方信息
- 申领者仅在**被选中后**，地址才对赠主可见
- 申领者的联系方式仅用于物流，不得另作他用
- 平台不存储物流面单之外的敏感信息

## 五、反馈闭环

### 5.1 流程

```
申领者收货 → 7天内提交反馈 → 赠主收到通知 → 交易完成
                  ↓
           超时未反馈 → 申领者信用扣分
```

### 5.2 反馈内容

| 内容 | 要求 |
|------|------|
| 物品使用照片 | ✅ 必须，至少 1 张 |
| 感谢信/感言 | ✅ 必须，文字或视频 |
| 小红花 | 赠主每完成一次赠与，自动获得 1 朵小红花（荣誉象征，非货币） |

### 5.3 规则

| 规则 | 说明 |
|------|------|
| 反馈时限 | 收货后 **7 天内**提交 |
| 超时处理 | 系统自动提醒；超时 14 天仍未反馈，申领者信用扣分 |
| 赠主可见 | 小红花和感谢信展示在赠主个人主页 |
| 反馈质量 | 敷衍反馈（如只发一个句号）可由赠主举报 |

## 六、激励机制（赠主侧）

赠主的核心驱动力是**赠予的快乐**，不是物质回报。激励围绕「认可」展开：

| 激励方式 | 说明 |
|----------|------|
| 🌸 小红花 | 每完成一次赠与获得 1 朵，累计展示在个人主页 |
| 📬 感谢信墙 | 收到的所有感谢信集中展示 |
| 🏆 里程碑 | 累计赠与 10/50/100 件获得徽章 |
| 📖 赠与故事 | 特别感人的赠与经历可被平台精选展示（需双方同意） |

> **不做**：排行榜、现金奖励、积分兑换。保持纯粹。

## 七、防作弊机制

### 7.1 防虚假赠与

| 风险 | 对策 |
|------|------|
| 赠主与申领者是同一人（自导自演刷小红花） | 同一设备/微信/手机号不能在赠与闭环中同时担任两方；异常模式检测 |
| 赠主发布虚假物品 | 申领者可举报；累计被举报 3 次，赠主账号冻结 |
| 申领者收到后转卖 | 申领者被举报查实后永久封禁 |

### 7.2 防机器人/批量申领

| 风险 | 对策 |
|------|------|
| 机器人批量申领 | 微信授权 + 实名认证 + 行为频率限制 |
| 同一人注册多个申领账号 | 实名信息去重，同一身份证只能绑定一个申领者账号 |
| 申领理由全是模板复制 | 系统检测高度相似的申领理由，标记可疑 |

### 7.3 举报与申诉

- 任何用户可举报违规行为，需附证据
- 被举报方有 3 天申诉期
- 平台运营方人工复核

### 7.4 运营底线

- 赠主和申领者均不涉及金钱交易（运费除外）
- 严禁私下索要金钱、红包、等价物
- 违者永久封禁
